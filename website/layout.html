NXRS

An experimental Rust-based firmware development environment on top of NuttX.

Embedded projects repeatedly need similar pieces: hardware access, data processing, communication and recovery. The difficult part is making those pieces reusable without losing track of the constraints of a particular device.

NXRS explores ordinary Rust std, threads and event-driven components for that work. NuttX provides the RTOS and board support. The aim is to keep application code familiar while making hardware boundaries and resource costs explicit.

Read the reasoning behind NXRS →

Still an experiment

The questions include portability, memory use, timing and the maintenance cost of the Rust/NuttX integration. Working examples are a way to investigate those questions, not a claim of general production readiness.

Architecture at a glance

NuttX supplies the operating system. Rust std and peripheral wrappers connect that foundation to reusable firmware components; platform profiles describe the product's bindings.

Architecture overview · Engineering reference

Examples and evidence

The finite navigation example exercises service composition and shutdown with synthetic inputs. The camera work adds capture, detection, gateway delivery and client-visible state. They exercise different parts of the environment.

Neither a host test nor a successful build proves board-level behavior. Resource measurements and qualification reports apply to the configurations they record. Additional examples and measurements are added as the project develops.
